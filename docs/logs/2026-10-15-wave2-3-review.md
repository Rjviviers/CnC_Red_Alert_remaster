## CI fix after the merges: `s07a_stamp_test` on MSVC
- **Symptom:** CI run 22 (Windows/MSVC) failed `s07a_stamp_test` (the 4 clipping cases); Linux passed. Nothing the test compiles had
  changed since the last green run, so the failure depended on run-time state.
- **Root cause:** `Init_Stamps` caches the icon set by address (faithful to `STAMP.ASM`). Each test builds its icon set in a new
  `std::vector`; MSVC's heap gave a new set the address of an earlier test's freed set, so it was drawn with the stale header.
- **Reproduced on Linux** by building two different sets in the same buffer: the 4x4 icon drew 0 rows (stale height 1).
- **Fix:** the test helper clears `LastIconset` for each new set. Production behaviour is unchanged. Documented the caveat in
  `surface-primitives.md`, and added a check to the S10 brief (theater reloads).
