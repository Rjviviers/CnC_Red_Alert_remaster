## Goal
Get the linked game as close to the main menu as possible without game data, so that the owner can download a CI
build, point it at their own Red Alert data and (ideally) reach the menu first time: fix the crash class S10b found
(writes into string literals), make the first run work without `SETUP.EXE` (generated `REDALERT.INI`, data folder
setting, clear "data missing" message), detect the expansions from their MIX files, skip the intro movies, add a boot
smoke test and downloadable CI builds, and write `docs/playing.md`.

The container has no Red Alert data and cannot download it, so nothing here was tested with real data.

### Which data files the game loads, in order (from the code)
Also in [playing.md](../playing.md#the-order-the-game-loads-them).
1. `REDALERT.INI` (game folder; created if missing). Start-up check: `REDALERT.MIX` (or `LOCAL.MIX`), `MAIN.MIX` (or `CONQUER.MIX`).
2. Window (`InitDDraw`), timer, audio, keyboard, mouse.
3. `Init_Keys` (built in), `Bootstrap` → `Init_Bootstrap_Mixfiles`: `EXPAND2.MIX` (optional), `HIRES1.MIX`,
   `EXPAND.MIX` (optional), `REDALERT.MIX`, `LOCAL.MIX` + `HIRES.MIX` (cached, inside `REDALERT.MIX`), `NCHIRES.MIX`.
4. `Init_Fonts`: `12METFNT.FNT`, `HELP.FNT`, `6POINT.FNT`, `GRAD6FNT.FNT`, `EDITFNT.FNT`, `8POINT.FNT`, `3POINT.FNT`,
   `SCOREFNT.FNT`, `LED.FNT`, `VCR.FNT`; `CONQUER.ENG`, `DEBUG.ENG`, `TEMPERAT.PAL`; `SC*.MIX`/`SS*.MIX` (game folder).
5. `Init_Mouse`: `MOUSE.SHP`. `Init_CDROM_Access`: nothing (search drives are set).
6. `Init_Secondary_Mixfiles`: `MAIN.MIX` → `CONQUER.MIX`, `GENERAL.MIX`, `MOVIES1.MIX`/`MOVIES2.MIX`, `SCORES.MIX`,
   `SPEECH.MIX`, `SOUNDS.MIX`, `RUSSIAN.MIX`, `ALLIES.MIX`.
7. `RULES.INI`; `AFTRMATH.INI` if Aftermath is present.
8. Intro skipped; `PALETTE.CPS`; `TITLE.PCX`; `Init_Bulk_Data` (caches `CONQUER.MIX`, sound MIX files, `TUTORIAL.INI`,
   all type shapes via `One_Time`); `Options.Load_Settings`; main menu.

## Decisions
- [ADR-0023](../decisions/0023-data-folder-and-first-run.md) (Proposed): data folder (`-data`, `[Data] Path`), search
  order (data → game → start-up folder; MIX files only, other files current directory first), first-run INI with
  documented defaults next to the executable, start-up checks with a message instead of a crash, no CDs,
  `[Intro] PlayIntro` ignored, expansions from `EXPAND.MIX`/`EXPAND2.MIX`.
- Exit code 1 for "data missing" (it is an error; the original's "Run SETUP" exited 0).
- A `-data` folder that does not exist is an error, even if the files are found elsewhere (a typo should not silently
  load other data).
- `HIRES1.MIX` missing is a warning, not an error (the original asserted in debug builds and carried on in release).
- Asserts stay compiled in (no `NDEBUG`); `Assert_Failure` was made safe before the fonts exist.
- CI ships the VC++ runtime DLLs next to `ra95.exe` instead of switching to the static runtime (`/MT`), to keep the CI
  build identical to a developer build.

## Determinism impact
No simulation code, random numbers, network event layout or object iteration order changed. Near it:
- **Expansion detection** now returns true when `EXPAND.MIX`/`EXPAND2.MIX` are present (S10b's registry stubs always
  said false). With Aftermath present, `Init_Game` processes `AFTRMATH.INI` into `Rule` and multiplayer sets
  `bAftermathMultiplayer` — exactly as the original with the expansion installed. Two players with different data
  therefore run different rules unless the lobby's Aftermath flag negotiation (ADR-0011, S13) handles it; that is the
  original behaviour.
- **MIX search order:** when the same MIX file exists in several folders, the data folder's copy wins (the original
  preferred the current directory). Different copies of the data are a sync risk regardless.
- `MixFileClass::Offset` hashes the same upper-cased name; only the side effect of upper-casing the caller's buffer is
  gone. Scenario names are parsed (`Set_Scenario_Name`) before any file is opened, so nothing read them upper-cased.
- `SidebarClass::Reload_Sidebar` loads the same shapes.

## Problems & open questions
- **Not tested with real data.** Further crashes after `Init_Bootstrap_Mixfiles` are likely; the owner's first run will
  show them (stderr, `ASSERT.TXT`, a gdb backtrace).
- `Is_DVD_Installed` still reads the real registry on Windows; a machine with an old RA DVD install would set
  `bUsingDVD`. Harmless now that `Force_CD_Available` always succeeds, but the DVD code could be removed.
- `SC*.MIX`/`SS*.MIX` (scenario packs) are still only looked for in the game folder (`_dos_findfirst`, readdir order).
- The `-480` option is overridden by `REDALERT.INI`'s `Resolution` (original behaviour; documented).
- The game rewrites `REDALERT.INI` when it saves options, which drops the comments of the generated file.
- S10b's suggested scan for other `extern` declarations whose type differs from the definition (like `GameInFocus`)
  was not done; GCC `-flto -Wodr` could find them.
- On a GUI-subsystem Windows build, stderr output only reaches a console or pipe that the launcher provides; the smoke
  test relies on CMake's pipes (to be confirmed by CI).

## CI fix: Windows game build (orchestrator, 2026-10-15)
- **Symptom:** CI run 35 was the first to build `ra95.exe` on Windows. It failed in `WIN32LIB/AUDIO/audio_sdl3.cpp`:
  `SDL_stdinc.h(1187): error C2118: negative subscript`, which is SDL's `SDL_alignment_test` compile-time assert.
- **Root cause:** the game libraries use global 1-byte packing (`/Zp1`, ADR-0014). On GCC, `ra_compat.h` pre-includes SDL under
  natural packing; on MSVC it relied on SDL pushing its own packing, but `SDL_begin_code.h`'s push comes *after* that assert.
- **Reproduced on Linux:** compiling `audio_sdl3.cpp` with `-fpack-struct=1` and without the pre-include fails on the same assert.
- **Fix:** `audio_sdl3.cpp` includes `<SDL3/SDL.h>` inside `#pragma pack(push, 8)`/`pop` on every compiler. The wrong comment in
  `ra_compat.h` is corrected. The repro compiles with 0 errors; the full Linux build and `ctest` (35/35) pass.
- **Second failure (CI run 36):** after the packing fix the Windows game build failed again within seconds. MSVC's compile-progress
  numbers had never been checked since Wave 3, because that step only reports. So `compile_progress.py --list-failures` was added (it
  prints every failing file with its first error), and on Windows the report now runs *before* the game build. The next run's log will
  give the complete list of MSVC errors at once.
- **MSVC error list (CI run 37):** with `--list-failures`, MSVC compiled only **131 of 314** files (Linux: 314/314). This number had only been
  reported, never enforced, since Wave 3. Grouped by first error:
  - 164 files: `CCFILE.H(105)` `class MixFileClass<CDFileClass>;`, a Watcom "instantiate this" line that MSVC reads as an undefined explicit
    specialization (C2906). Now under `#ifdef __WATCOMC__`, as S06b did for `FUNCTION.H`.
  - 1 file (`WIN32LIB/MISC/DELAY.CPP`): the Windows SDK's own headers broke (`'int' followed by 'int'`). **Root cause:** a stale copy
    `WIN32LIB/MISC/WWSTD.H` (still with `#define VOID void` / `#define INT int`) sat next to `DELAY.CPP`. On case-insensitive Windows,
    `#include "wwstd.h"` picks the local stale copy; on Linux the lower-case name doesn't match it, so the fixed `WIN32LIB/INCLUDE` copy is
    used. Five more shadowing copies differed from `WIN32LIB/INCLUDE` (`DRAWBUFF/GBUFFER.H`, `TIMER/TIMER.H`, `SHAPE/SHAPE.H`,
    `AUDIO/SOSRES.H`, `RAWFILE/RAWFILE.H`). All six stale copies are deleted; `WIN32LIB/INCLUDE` is the single source of truth. New CI step
    `scripts/check_shadow_headers.py` fails if a differing copy comes back.
  - Small one-offs: `SEEK_CUR` (`WWFILE.H` now includes `<stdio.h>`), `PATH_MAX` (defined as 260 for MSVC in `ra_compat.h`), `FIXED.CPP`
    (`strchr` on a const string returns `char const *`), `SEARCH.H` (`static` on an out-of-class member definition), `ROTBMP.CPP` (implicit
    `int` return), `VQAPLAYP.H` (`void (__cdecl *UnVQ)(...)`: calling convention inside the declarator), `VERTAG.CPP` (C++11 literal suffix,
    so spaces between the string literals), and an extra `GraphicBufferClass::` qualifier in `GBUFFER.H` (Windows-only branch).
  - `WINVQ/VQM32/TESTVB.CPP` left the build: a DOS port-I/O vertical-blank test whose only callers (`VIDEO.CPP`, the VQA loader) are
    already out of the build.
  - Verified on Linux: full build, 313/313 compile, `ctest` 35/35. Affected files syntax-checked with MinGW (real Windows headers). Each
    error above was only the *first* in its file, so CI may reveal more; the next run's list will show them.
