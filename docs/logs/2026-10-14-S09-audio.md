## Goal
Replace DirectSound (and what was left of HMI SOS) in `WIN32LIB/AUDIO` with a portable design: a backend
interface with a null backend (so S10 can boot), C++ decoders for the AUD formats (old package S07-E), a software
mixer that keeps the original volume/priority behaviour, and an SDL3 backend.

## What was done
1. Read the audio library (`SOUNDIO.CPP`, `SOUNDINT.CPP`, `SOUNDLCK.CPP`, the three asm decoders) and every game
   caller. Wrote down the original design, AUD format and quirks in [audio.md](../codebase/audio.md).
2. Decoders: translated `AUDUNCMP.ASM` (Westwood ADPCM) and `OLSOSDEC.ASM` (general IMA ADPCM) to C++; replaced
   `SOSCODEC.ASM` with `CODE/ADPCM.CPP`'s table-driven loop, fixing its size/return/state semantics to match the asm
   (details in audio.md §3). Deleted the three `.ASM` files and their `.INC` tables.
3. Mixer (`audio_mixer.cpp`): pull-model voices with an 8 KB staging buffer (the old fill size, so `Sample_Copy` is
   unchanged), linear resampling, 16.16 gains, clipping, 40 Hz tick for `maintenance_callback`, one recursive lock.
4. Backend interface (`audio_backend.h`), null backend (`audio_null.cpp`), SDL3 backend (`audio_sdl3.cpp`, `#ifdef RA_HAVE_SDL3`).
5. Rewrote `SOUNDIO.CPP`/`SOUNDINT.CPP`/`SOUNDLCK.CPP` on top of the mixer, keeping every public signature in
   `audio.h`; removed all Win32/DirectSound/`wwstd.h` dependencies (`audio_compat.h`).
6. Tests (`tests/s09_*.cpp`), docs, inventory rows.

Dead ends / findings along the way:
- First all-pass of the threaded test was hollow: the pump thread ran so fast the real-time-start stream starved and
  "ended". Reworked it to throttle the thread, play effects at volume 0 and compare the captured score bit-exactly.
- The null backend originally advanced time only in `Sound_Callback`; the game busy-waits with
  `while (Is_Speaking()) {};` (`CODE/SCENARIO.CPP:822`), which would hang. `Sample_Status` now advances it too (test added).
- With the build's 1-byte struct packing a `std::recursive_mutex` member could be misaligned (futex needs 4-byte
  alignment); the mixer allocates its mutex on the heap.
- Coordinator note mid-session: S08 merged SDL3 3.4 (target via `cmake/RASDL3.cmake`). Per instructions I kept the
  `RA_HAVE_SDL3` option instead of re-wiring S08's CMake; the backend uses only SDL's audio API (fine for
  `RA_SDL3_HEADLESS`) and no SDL types leak into `audio.h`.

## Decisions
No ADR needed (no format/protocol change; ADR-0004 and ADR-0010 cover the direction). Small decisions:
- Pull-model mixer, one voice per tracker; decoding happens on the audio thread under the lock, file I/O stays on the game thread.
- Keep the original volume curve (DirectSound hundredths-of-dB → `10^(ds/2000)`), priority rules, ignored pan, and quirks (audio.md §4).
- `Audio_Init` fails (game runs silent, as with no sound card) if the backend can't open; the null backend always opens.
- `Sample_Copy` rewinds on an incomplete/oversized frame instead of desynchronising (identical output for good data).
- Memory via `malloc`/`free` instead of the library's `Alloc` (no dependency on `WIN32LIB/MEM`).
